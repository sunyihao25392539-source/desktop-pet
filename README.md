# 金丝猴桌面宠物

第一版桌面宠物原型：小眼睛金丝猴拿樱桃，作为送给她的版本。

当前默认运行版本：GoldenMonkeyPet-v14.exe

v7 修复：使用四帧小步行走素材，修复脚部色块；移动与步伐分频，避免眨眼与行走互相覆盖。退出旧版后重新运行启动脚本生效。

v8 修复：加入短暂原地转身过渡，换方向前先收窄身体再进入步行，减少突然反向滑步的感觉。

v9 修复：左右移动时使用对应朝向，尾巴会随朝向换边；右键菜单加入“停止走动/恢复走动”开关。

## 运行

v14：移除底部状态条，改为头顶奶油色小气泡。忙碌时三点轻跳、等待确认时暖橙提示；本轮结束或中断显示六秒后收起，空闲不显示。未连接时短暂显示“待连接”后缩为小圆环，悬停可查看完整状态。留言与睡眠 Zzz 出现时暂时让出气泡位置。Hooks 通过独立 console 桥接程序 GoldenMonkeyCodexHook.exe 写入同一状态目录，v14 负责新的显示界面。

v13：接入 Codex 官方 Hooks，本地接收任务开始、工具调用、权限请求、本轮结束、中断和会话关闭事件。下方状态栏显示工作阶段与并行任务数，工作时停止自主走动并看樱桃，等待权限时歪头。手动睡觉不被打断。尚未收到事件时显示“等待连接”；超过 30 分钟没有更新的活动任务显示“状态待更新”，不是已完成。Stop 仅代表本轮结束，不保证任务成功，也可能被其他 Stop hook 继续。

### Codex 联动安装与验证

1. 执行 `powershell -NoProfile -File .\tools\build.ps1` 构建宠物本体和 GoldenMonkeyCodexHook.exe。
2. `tools/codex-hooks.json` 包含七个纯状态上报 hook；命令指向本项目 GoldenMonkeyCodexHook.exe 的绝对路径，移动项目后需更新。
3. 执行 `powershell -NoProfile -File .\tools\install-codex-hooks.ps1`，向用户 `.codex/hooks.json` 安装。若已有该文件，安装器会停止以保留原配置。安装在用户层是为了观察不同项目的本地任务；原有 config.toml 的 notify 不变。
4. Codex 要求用户审核并信任新 hook 的具体定义；未经信任的 hook 会被跳过。官方 CLI 入口为 `/hooks`。重新打开相关会话，按 Codex 提示完成信任，再启动一项真实任务。
5. 退出旧宠物，运行 run_pet.bat；检查“等待连接 → 正在工作/执行工具 → 本轮已结束”。只有这组真实事件验证过才算桌面端联调成功；单元测试不等于已连接桌面端。

状态数据位于被 Git 忽略的 `runtime/codex-status/`，只保存会话/轮次标识、时间、状态和工具类别，不保存提示词、代码、工具参数或回复内容。未覆盖托管搜索、崩溃退出等无对应 hook 的路径；等待权限的清除依赖工具返回或轮次结束。脚本不输出模型上下文，也不批准或阻止操作。取消联动可在 Codex 的 hook 管理中禁用这七项；若 hooks.json 仅含本项目的配置，也可移除该配置文件。

官方机制与信任要求：https://learn.chatgpt.com/docs/hooks

v12：单击头部或右键“摸摸头”会歪头回应并冒两颗爱心；单击等待系统双击判定后触发，拖拽和双击不额外触发摸头。睡觉时摸头不会叫醒，仍使用双击叫醒。清醒待机时偶尔歪头、看看樱桃、整理尾巴；停止走动后也会做小动作。动作保持左右朝向，睡觉和拖动会打断动作。

v11：专用抱樱桃蜷坐睡姿，约 3.2 秒一轮的轻微呼吸，偶尔浮出 Zzz；叫醒时先睁眼抬头再站起，喂食唤醒也保留抬头过渡。左右睡姿和醒来姿势同步朝向，呼吸保持脚底位置不变。素材为内置 imagegen 生成的透明双帧图 assets/sprites/sleep_seated_sheet.png，程序按比例裁切并适配透明窗口显示。

v10：统一管理待机、走动、转身、表情、拖拽、回弹和睡觉状态。右键“睡觉/叫醒”，睡觉时闭眼且停止自主走动、眨眼和随机爱心；双击可唤醒，投喂或留言也会唤醒。睡着时仍可拖动，松手继续睡觉。暂停走动的设置会保留到醒来后。眨眼和开心表情保持当前朝向。

```powershell
.\run_pet.bat
```
